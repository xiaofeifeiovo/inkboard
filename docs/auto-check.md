# 自动错误检查（设计）

状态：**已实现（2026-11-25）**。本文作为设计记录保留，实现结构、接口约定与测试方式见 `AGENTS.md` 的「自动检查」小节。

这个功能建立在已经实现的分块（`InkLayout`）和装页（`PageAssembler`）之上，见 `AGENTS.md` 的「分块与装页」。

## 1. 目标

用户书写时，把已经写完的块发给 AI，让它结合前面的内容判断这个块有没有错误，再把结果标在画板上。

## 2. 期望功能（用户看到的）

### 开关

- 由一个按钮启动，**默认关闭**。
- 打开时如果画板上已经有内容，先把已有内容全部检查一遍（见 4.3），之后每写完一个块检查一次。

### 标注

| 结果 | 标注 | 例子 |
| --- | --- | --- |
| 严重错误，会影响后面的推导 | 红框 | 公式写错、定义错误 |
| 描述不准确，但不算严重 | 黄框 | 漏写了一个下标 |
| 没有问题 | 不标 | |

- 框**按块**画，不按行。具体是哪一行、哪里错了，写在详情里。
- 一个块有多个问题时，框的颜色取最严重的那个。

### 框右下角的三个按钮（红框、黄框都有）

- **详情**：显示 AI 的评价：哪里错了、为什么、应该怎样。同时显示 AI 读到的内容（转写），方便用户看出是不是 AI 认错了字。如果 AI 注明了"相关：第 N 块"，详情里同时高亮那个块。
- **忽视**：不再显示这个框。
- **重新检查**：把这个块重新发给 AI 判断（讨论时曾叫「更正」，因为容易被理解成"让 AI 改正"而改名）。

### 修改过的块

- 已经检查过的块被修改后，**不会自动重新发送**，要等用户点「重新检查」。
- 原来有红框、黄框的块被修改后，框变成灰色虚线并显示「重新检查」，不让红框留在已经改过的内容上。
- 原来没有问题（没有框）的块被修改后，也在它右下角显示「重新检查」按钮。

### 最新写的块

触发规则是"开始写另一个块"（见第 3 节），所以用户写完最后一个块就停笔时，这个块不会被自动检查。初版设想在最新写的块右下角放一个小的「检查」按钮并配快捷键（最终实现改为不在正在书写的块上放画布按钮，而是放进工具栏下拉菜单和 ⇧⌘K，见第 10 节）。

### 其他

- 正在检查时显示一个不打扰书写的提示（最终实现放在工具栏按钮与下拉菜单，`StatusBanner` 仅用于失败提示，见第 10 节）。
- 检查结果存进文稿，重新打开文件不用再检查一遍。

## 3. 什么时候算"一个块写完了"

- **只有一条规则：用户开始在另一个块里书写时，上一个块算写完。** 不用停笔计时，因为用户可能停下来思考。
- 每画完一笔重新分块，看这一笔属于哪个块：如果这个块不包含上一个书写块的笔画，上一个块就写完了，放进待检查队列。
- 同一时间只有一个请求在进行，期间写完的块排队，等下一次发送。
- 需要用真实笔迹验证的边界情况：
  - 书写过程中分块结果会变，比如新写的一行并入了已经检查过的段落。初步规则：刚检查完的那个块又多了新笔画（之前检查过的笔画都还在），算"接着写"，自动检查；其他已检查块的笔画有变化（擦掉、移动、回到前面的块添加内容），算"修改"，等用户点「重新检查」。
  - 可以按书写顺序回放 `test/未命名.inkboard` 的笔画，检查触发的时机和换页是否合理。

## 4. 上下文：按页分段的多轮对话

这是用户提出的折中方案，目的是省 token，同时让以后的文档转换能复用结果。

- 用已有的装页（`PageAssembler`，参数同全局转换，即 `AISettings.pageOptions`）把块按阅读顺序装成页。
- **当前页**对应一个多轮对话：每写完一个块追加一轮，只发这个块的图片，AI 只判断这个块。前面几轮的块图片都在对话历史里，AI 看到的是用户真实的笔迹。
- **前面的页**都已经转写成文字（Markdown），作为当前页对话开头的上下文，不再发图片。
- 对话最多只包含一页的块图片，所以长度有上限。
- 每页的转写和全局转换的结果是同一种东西，以后全局转换可以直接复用（见第 7 节）。

不采用的做法：

- **整个文稿一个长对话。** OpenAI 兼容接口不保存对话，每次请求都要把整段历史（包括之前所有块的图片）重发一遍，总花费大致随块数的平方增长；改了前面的块，还得从那里开始重放后面的所有轮。
- **每次只发前面各块的转写、每个请求独立。** 当前页里也只能看到转写，AI 认错的字会直接影响后面的判断。

### 4.1 页一旦转写就固定

现在的装页每次都按所有块重新计算：前面某块改高了，后面的分页位置都会变。所以：

- 一页转写完成后，把它包含的笔画（id 集合）和转写一起存进文稿，这一页就固定了。
- 之后装页只排还没固定的块，接在已固定的页后面。

### 4.2 换页

一个块写完时：

1. 看它还能不能放进当前页。能放下，就在当前页的对话里追加一轮。
2. 放不下：先转写当前页并把它固定，然后开一个新对话，以前面各页的转写作为上下文，检查这个块。
3. 所以每页的第一个块要等上一页转写完才能检查，每页只等这一次。

页的转写是一个单独的请求（新的 ACP 会话，或一次独立的 API 请求）：发整页图片，图上用编号标出每个块（类似「识别分块类型」的红框编号）。要求：

- 输出 Markdown，每个块的内容前加一个块号注释，比如 `<!-- B12 -->`。这样能知道每段文字属于哪个块（4.4 要用），全局转换时去掉注释就是普通 Markdown。
- **照原样转写，不要改正错误**：后面的检查要基于用户实际写的内容。

### 4.3 打开开关时检查已有内容

- 按页处理，每页一次请求：发这一页的图片（标好块号），前面的页用转写作为上下文。一次请求同时返回这一页每个块的检查结果和这一页的转写。AI 可以一次返回多个错误。
- 内容的最后一页往往还没写满，它的请求就是当前页对话的第一轮，之后写的块接着在这个对话里发。

### 4.4 修改之后的重新检查

都在用户点「重新检查」之后才发：

- **改的是当前页的块**：在当前对话里追加一轮，只发这个块的新图片，告诉 AI 这个块已经改过，之前的版本作废，让它重新判断这个块和它后面的块。后面那些块的图片 AI 已经看过，不用重发。
- **改的是已固定页里的块**：按 4.3 的格式重发这一页（标出改过的块），一次拿到检查结果和这一页的新转写，替换存下的转写。
- **更后面的已固定页**：它们的转写没变，只是判断可能变了（前提改了）。用一次纯文字请求，发各页转写，让 AI 重新判断，结果按块号对应回去，不用重发图片。

用户最初的要求是：前面的块上下文不变，当前块重新发送，后面的块也重新发送。上面的做法满足这个要求，只是后面的块尽量只发文字。

### 4.5 对话丢失时重建

agent 崩溃、设置改了导致重启，或者重新打开文稿时，当前页的对话就没了。这时开一个新对话，把前面各页的转写和当前页已检查的块图片（连同之前的检查结果）一次发过去，然后继续。对话本身不存进文稿。

### 4.6 块号

- 块号（B1、B2…）只用于和 AI 交流；程序内部按笔画 id 集合识别一个块（和 `Board.labels` 一样）。
- 在同一个对话里，块号不能变。所以块号在第一次发送时分配，之后保持不变，不随阅读顺序重新编号。

## 5. 后端

### ACP：多轮会话

- ACP 协议本身支持多轮：同一个会话里多次调用 `session/prompt`，历史由 agent 保存。
- 现在的 `ACPAgent.prompt` 每发完一次就关闭会话（`ACP.swift` 里 `defer { close(...) }`）。需要增加一个保持打开、可以连续发送的会话对象。
- 每页开一个新会话，不用重启 agent 进程（`prepare()` 已经会提前准备一个空闲会话）。代价是 agent 的系统提示每页多发一次。
- 不引入第三方 ACP SDK：官方 SDK 没有 Swift 版；社区的 Swift 版（aptove/swift-sdk）会成为项目的第一个第三方依赖；而且收发消息这一层已经写好了。

### OpenAI 兼容 API

- 接口不保存对话，多轮就是程序自己保存消息列表（user 消息和 assistant 回答交替），每次整段发送。
- 历史只在末尾追加，能命中服务商的前缀缓存（OpenAI 等会对重复的开头自动打折）。

### 接口草案

在 `ModelBackend` 上增加对话，比如：

```swift
protocol ModelConversation: AnyObject {
    /// 追加一轮，返回回答。
    func send(_ parts: [PromptPart]) async throws -> String
    func close()
}

extension ModelBackend {
    func openConversation(model: String, thoughtLevel: String) async throws -> ModelConversation
}
```

### 设置

- 自动检查单独选模型和思考档位（两种后端各一套，和现有的公式 / 文档设置一样）。可以选更便宜、更快的模型。
- 自动检查的请求很频繁。ACP agent 每个会话都带着它自己很长的系统提示，成本和延迟都更高，所以这个功能更适合用 OpenAI 兼容 API。两种都要支持。
- 判断数学推导需要推理模型，一次请求可能要十几秒到几十秒。

## 6. 提示词与回答格式（草案）

### 检查（每一轮）

提示词要点：

- 角色：检查手写笔记，只判断这一次给出的块（全量检查时是这一页的所有块）。
- 严重程度的定义：`error` 是严重错误、会影响后面的推导（公式写错、定义错误）；`warning` 是描述不准确但不严重（漏写下标）；没有问题就是 `ok`。
- 前面已经标出的错误，由它推出的后续结果不要重复报。
- 如果问题和前面某个块有关（比如互相矛盾），在 `related` 里写出那个块的块号。
- 看不清写的是什么时，不要判为错误。
- 只输出 JSON，不要用代码块包起来，不要调用任何工具（ACP agent 需要这句）。

回答格式：

```json
{
  "blocks": [
    {
      "id": "B12",
      "reading": "AI 读到的内容（公式用 LaTeX）",
      "issues": [
        {
          "severity": "error",
          "summary": "一句话说明",
          "detail": "哪一行、哪里错了、为什么、应该怎样",
          "related": ["B5"]
        }
      ]
    }
  ]
}
```

- `issues` 为空表示没有问题。
- 解析要宽容，参考 `BlockLabeling.parse`：容忍代码块包裹、大小写不一致，跳过未知块号和未知的严重程度。

### 页转写

- 提示词以全局转换的文档提示词为基础，加上 4.2 的两条要求（块号注释、照原样转写）。
- 4.3 和 4.4 里"一次请求同时返回检查结果和页转写"时，可以在上面的 JSON 里加一个 `"page"` 字段放 Markdown。Markdown 放进 JSON 需要转义，模型偶尔会出错；如果实测不可靠，改成先输出 Markdown、最后再输出一个 JSON 块。

## 7. 存储（文稿）

- 和 `labels` 一样，作为 `.inkboard` 文件里的可选字段，按笔画 id 集合存储：
  - `checks`：每个块的块号、笔画集合、AI 读到的内容、问题列表、是否已忽视。
  - `pages`：已固定的页的笔画集合和转写（带块号注释的 Markdown）。
- 存储的笔画集合和当前块的笔画对不上，就说明这个块被改过，显示为"待重新检查"。
- 检查结果是异步回来的，用户可能还在写字，所以**不进撤销栈**（否则用户按 ⌘Z 想撤销一笔，撤销掉的却是检查结果）。但要用 `updateChangeCount(.changeDone)` 标记文稿已编辑，否则不会存储（见 `AGENTS.md`：「已编辑」状态来自撤销注册）。「忽视」是否可撤销待定。
- 是否把文件格式升到 version 3：旧版本的程序打开再存储会丢掉不认识的字段。待定。
- 全局转换：已固定、没有改过的页直接使用存下的转写，只转换改过的和还没固定的部分。

## 8. 界面

- 画在 `CanvasView` 的覆盖层上，类似「显示分块」：框是覆盖层，不改笔迹。
- 框的位置用块的 `bounds`。贴图上的墨迹（figure 的子块）也要能标。
- 右下角的按钮点击要优先于当前工具，不能在按钮上开始画笔画。
- 详情用 `NSPopover`。
- 颜色：红、黄（偏橙一些，在白底上看得清）、灰色虚线（已修改，待重新检查）。

## 9. 已经确定的决定

- 由按钮启动，默认关闭。
- 上下文用按页分段的多轮对话（第 4 节）。
- 只在开始写另一个块时触发，不用停笔计时。
- 按块框出错误，细节写在详情里。
- 修改过的块不自动重新发送，等用户点「重新检查」。
- 问题可以注明"相关：第 N 块"，详情里同时高亮。
- 检查结果存进文稿。
- 按钮叫「详情」「忽视」「重新检查」。
- ACP 多轮会话在现有客户端上实现，不引入第三方 SDK。

## 10. 已决定

以下是在实现阶段对原待定问题做出的决定和理由：

| 问题 | 决定与理由 |
| --- | --- |
| 开关放在哪里，是否按文稿记住 | 工具栏分体按钮「自动检查」：主体切换开关，图标区分关 / 开 / 检查中 / 失败；箭头打开下拉菜单，列出正在检查、排队中、正在书写的块和失败信息（点块条目滚动并短暂高亮该块）。另有菜单「转换 → 自动检查」（带勾选状态）。**按文稿记住**（存在 `AutoCheckState.enabled`，默认关）。打开开关时全量检查开放页上未检查和改过的块（已固定页不自动检查；在「AI 辅助」分块模式下，若还有笔迹不在任何 AI 分组里，会先做一次「AI 识别分块」，可取消，失败时改用本地分块继续）；**打开一个开关本就开着的文稿时不会自动全量检查**，避免打开文件就消耗额度，之后新写的块照常检查，未检查的块显示「检查」按钮。 |
| 最新块「检查」按钮与快捷键 | 快捷键 ⇧⌘K，菜单「转换 → 检查最新的块」（正在书写时工具栏下拉菜单里也提供同一项）。画布上没检查过、没在排队、也不是正在书写的块右下角显示小的「检查」按钮（不只是最新的块）。**排队、检查中和正在书写的块在画布上不显示任何标记**（避免干扰阅读，信息移到工具栏下拉菜单；已有红/黄框的块重新检查时保留框）；正在往已检查的块里继续写（未擦除旧笔画）时同样不显示。进度不再用横幅，只有失败时显示错误横幅和「重试」。 |
| 页转写放进 JSON 还是分开 | **分开**。JSON 字符串里的 LaTeX 反斜杠很容易出错，因此页请求的回答格式定为：JSON → 单独一行 `<!-- PAGE -->` → Markdown（纯转写请求只输出 Markdown）。如果页请求回答缺少转写，再单独补发一次转写请求。 |
| 全局转换：直接拼接还是让 AI 整理 | **直接拼接**：从第一页开始，连续且没有改动的已固定页直接使用存下的转写（去掉 `<!-- Bn -->` 块号注释），其余部分照旧渲染发给 AI 并接在后面；横幅会提示前几页沿用了自动检查的转写；全部可复用时不发请求。 |
| 文件格式是否升到 version 3 | **不升**，仍是 version 2，增加可选顶层字段 `autoCheck`（为空时省略）。理由：旧程序读取时不校验 version，升级版本号也挡不住旧程序丢掉不认识的字段。 |
| 贴图怎么检查 | 纯贴图（`image` 块）不检查、不画框；贴图上的墨迹（`figure` 的每个子块）作为独立的检查单元。贴图里的印刷内容算上下文：渲染单块图片和页图片时都会把下面的贴图一起画出来。 |
| 书写过程中分块变化的拆分与合并规则 | 通过按书写顺序回放真实笔迹 `test/未命名.inkboard` 验证后定下：①「接着写」：写完的块只是在原来基础上变大（已检查的笔画一笔没少），且包含最近一次发送的块，自动重新检查；②书写时几个已检查的块合并成一块（例如推导的多行公式连成一个公式块），视为接着写自动重查，合并后沿用重合笔画最多的块号（平局取较小块号），其余被合并块号的旧结果替换清除；③其他修改（擦掉、移动、回到前面的块添加内容）等用户点「重新检查」；④书写过程中一块被拆开时，留下的部分算写完，立即检查；⑤笔迹未变、仅因「AI 识别分块」（或其撤销/重做）、「识别分块类型」或切换分块方式引起分组变化时，开放页上原本已检查且未改过笔迹、仅因分组被合并或拆开的块自动重新检查。 |
| 「忽视」是否可撤销 | **不可撤销**，和检查结果、开关状态一样不进撤销栈，改动时通过 `updateChangeCount(.changeDone)` 标记文稿已编辑。重新检查后清除忽视状态（作为后续块被重判且问题列表变化时也清除）。 |
| 自动检查的模型设置 | 设置里为两种后端各存一套「自动检查（提示词是固定的）」模型和思考档位（`ai.check.*` / `ai.api.check.*`），默认留空即「与全局转换相同」；选「与全局转换相同」时思考档位一并跟随全局转换（弹出菜单不可用）。改变方式、agent/API 或实际使用的模型和档位时，当前页对话丢弃重建。 |
| 出错处理 | 不弹模态框，在检查专用的 `StatusBanner` 和工具栏下拉菜单里显示错误和「重试」（工具栏图标变为警告标志）；队列暂停，直到用户点「重试」或手动点某个块的「检查」/「重新检查」。 |

## 13. 已知限制

- **排队期间继续书写**：排队的块在轮到发送时按当时的实际笔画渲染发送，因此排队期间继续往该块写的笔画会一起发出。
- **回到前面的块书写**：回到前面的块添加内容时，会让当前正在写的块立即算作写完并自动发送（哪怕只有一笔）。
- **单笔临时成块**：书写过程中如果先在较远处落下一笔再补写中间部分，分块偶尔会把那单独一笔先当成一个块发送（之后并入整块时会合并替换；放宽同行水平连接后，`test/未命名.inkboard` 逐笔回放中已不再出现）。
- **尚未用真实模型测试**：目前全部通过模拟 agent、`StubHTTP` 和假 `AutoCheckService` 验证，实际模型对提示词的遵循度与延迟尚未实测（会消耗额度，需用户同意后再测）。
